What to merge

How it works

  1. Binance transaction history (UTC_Time, Account, Operation, Coin, Change): reward-type operations (Simple Earn interest, staking rewards, distributions, airdrops, Launchpool, cashback, commissions) are merged per period, account, operation and coin. Trades, deposits, withdrawals and subscriptions/redemptions are left exactly as they are, because Koinly pairs them by timestamp.
  2. Koinly universal CSV: rows merge when they share label, currencies and period. Unlabeled one-sided rows (transfers between your own wallets) are left alone so Koinly can still match them. TxHash is cleared on merged rows and the description says how many rows were merged.
  3. Anything else (KuCoin or Pionex bot fills, Bybit, OKX…): choose the date column, the columns that must match, and the number columns to add.

The output keeps the original header and column order, so you import it into Koinly the same way you would the original file. Delete or replace the original import first, or you will double count.

FAQ

Is merging rewards allowed for tax purposes?

Koinly's support team recommends it on its own forum for exactly this problem (example, example). Daily merging keeps each day's income at that day's prices; weekly or monthly merging is coarser. Rules differ by country, and this is not tax advice. If in doubt, ask your accountant which period to use.

Does my data leave my computer?

No. The CSV is parsed and merged by JavaScript in this page. You can check the source or disconnect from the internet after the page loads.
